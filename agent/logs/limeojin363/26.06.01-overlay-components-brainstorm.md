# 오버레이 계열 컴포넌트 작업 브레인스토밍

- 방식: 서브에이전트 3개 병렬 요청, 2개 완료, 1개는 5분 대기 후 타임아웃.
- 로컬 확인: `apps/client`는 React 18, Emotion, React Router 중심이며 캘린더/지도 SDK 없음.
- 기존 자산: `components/BottomSheet`는 최소 셸, `components/OverlayBg`는 빈 div.
- 도메인 계약: 엔진 입력은 `schedule.dateISO`, `schedule.time24h`, `schedule.stayDurationMinutes`, `location: { lat, lng }[]`.
- 전제: 버튼은 외부 의존성이므로 이번 작업은 action UI를 직접 만들지 않는다.

## 결론

- 먼저 `Overlay` primitive를 만들고 그 위에 `Dialog`, `BottomSheet`를 얹는다.
- `DatePicker`, `LocationPicker`는 Overlay를 모르는 순수 content 컴포넌트로 둔다.
- 페이지는 어떤 오버레이가 열렸는지만 제어하고, picker는 draft/commit 계약만 가진다.
- 날짜/위치는 지금 SDK를 고르기보다 provider/slot 계약을 열어두는 편이 안전하다.

## 컴포넌트 분해

- `OverlayRoot`: portal, z-index, body scroll lock, ESC, outside click, focus restore.
- `OverlayScrim`: fixed full viewport 배경. 기존 `OverlayBg`를 이 역할로 채우거나 이름 변경.
- `Dialog`: 중앙 확인 모달. `role="dialog"`, `aria-modal`, title/description/content/footer slot.
- `BottomSheet`: 하단 표면. title, close, content, footer slot, max-height, internal scroll.
- `DatePicker`: 월 이동, 요일 헤더, 날짜 그리드, 선택 상태, disabled 날짜 정책.
- `LocationPicker`: 검색/현재 위치/지도 자리/결과 리스트/선택 요약을 담는 content.

## 권장 API

- `OverlayRoot`: `open`, `onOpenChange`, `onDismiss`, `children`, `closeOnScrimClick`.
- `Dialog`: `open`, `title`, `description`, `children`, `footerSlot`, `onDismiss`.
- `BottomSheet`: `open`, `title`, `children`, `footerSlot`, `onDismiss`, `maxHeight`.
- `DatePicker`: `value: string | null`, `onChangeDraft`, `minDate`, `maxDate`, `disabledDates`.
- `LocationPicker`: `value`, `onChangeDraft`, `searchProvider?`, `mapSlot?`, `currentLocationProvider?`.
- 공통 action 계약: `footerSlot` 또는 `actionsSlot({ canSubmit, commit, cancel })`.
- 버튼 텍스트/색/크기/로딩 상태는 여기서 결정하지 않는다.

## 상태 모델

- 페이지 overlay 상태는 여러 boolean 대신 discriminated union 권장.
- 예: `{ type: "none" } | { type: "confirm" } | { type: "date" } | { type: "location" }`.
- picker 내부는 draft를 다루고, 닫기 전 확인 시점에만 form state로 commit한다.
- 날짜 내부 draft는 `Date | null` 가능, 외부 제출 값은 반드시 `YYYY-MM-DD`.
- 위치 내부 draft는 `{ lat, lng, label?, address?, source? }`.
- 엔진 제출 직전에는 위치 표시 정보를 제거하고 `{ lat, lng }[]`로 축소한다.

## 접근성/모바일

- Dialog는 초기 포커스, Tab 순환, ESC 닫기, 닫힌 뒤 trigger 포커스 복귀가 필요하다.
- BottomSheet도 `aria-labelledby`와 닫기 동작을 제공하되 drag gesture는 2차 작업으로 미룬다.
- body scroll과 sheet 내부 scroll이 동시에 움직이지 않게 `max-height`와 `overscroll-behavior`를 둔다.
- iOS safe area를 위해 하단 padding에 `env(safe-area-inset-bottom)`를 고려한다.
- z-index 토큰은 최소 `scrim < sheet/dialog < toast` 계층으로 시작한다.

## 위치 선택 판단

- 현재 지도 SDK가 없으므로 지도 컴포넌트를 직접 확정하지 않는다.
- 첫 버전은 `mapSlot`에 placeholder 또는 외부 지도 구현을 끼울 수 있게 한다.
- 검색도 `searchProvider(query) => Promise<LocationCandidate[]>` 계약만 먼저 둔다.
- 후보 타입은 `id`, `label`, `address?`, `lat`, `lng`, `source` 정도면 충분하다.
- 현재 위치는 브라우저 권한/실패가 있으므로 provider를 분리하고 picker는 결과만 표시한다.

## 날짜 선택 판단

- 외부 캘린더 라이브러리 없이도 월 단위 그리드는 구현 가능하다.
- 시간/체류 시간까지 한 시트에 넣을지, 날짜만 담당할지는 페이지 UX에서 결정한다.
- 엔진 계약상 schedule은 하나의 묶음이므로 `ScheduleDraft`를 별도로 두는 편이 확장에 유리하다.
- 날짜 셀은 키보드 이동까지 고려하면 grid role 또는 button grid 정책을 초기에 정해야 한다.

## 작업 순서

- 1단계: `OverlayRoot`, `OverlayScrim`, z-index/safe-area/scroll lock 구현.
- 2단계: 기존 `BottomSheet`를 Overlay 기반으로 확장하고 `footerSlot`만 열어둔다.
- 3단계: `Dialog`를 같은 Overlay 기반으로 구현한다.
- 4단계: `DatePicker` 순수 content 구현 후 dateISO commit 어댑터를 붙인다.
- 5단계: `LocationPicker` 순수 content 구현 후 provider/slot 계약을 붙인다.
- 6단계: 추천 폼 페이지에서 overlay union state로 연결한다.

## 테스트 기준

- Overlay: 열림/닫힘, ESC, scrim click, scroll lock, focus restore.
- Dialog: role/name, footer slot 렌더, 외부 버튼 컴포넌트 주입 가능 여부.
- BottomSheet: viewport 하단 고정, max-height 내부 스크롤, safe-area padding.
- DatePicker: 월 이동, 날짜 선택, disabled 날짜, `YYYY-MM-DD` 변환.
- LocationPicker: 검색 결과 선택, 현재 위치 실패, `lat/lng` 없는 후보 차단.

## 리스크

- focus trap을 직접 만들면 누락 위험이 있다. 의존성 추가가 가능하면 전용 유틸 검토.
- 지도 SDK를 성급히 고르면 번들/키/권한 정책이 컴포넌트에 새어 들어간다.
- 버튼을 임시 구현하면 외부 버튼 작업과 충돌하므로 slot 계약만 남긴다.
- `OverlayBg` 이름은 배경만 뜻하므로 공통 레이어로 확장 시 명명 정리가 필요하다.
