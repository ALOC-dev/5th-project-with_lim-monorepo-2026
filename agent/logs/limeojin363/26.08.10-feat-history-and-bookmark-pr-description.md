# 추천 이력·저장 장소 연동 및 공통 UI 기반 적용

## PR 정보

- Base: `main`
- Head: `feat/history-and-bookmark`
- 비교 범위: `origin/main...HEAD`

## 요약

- 공통 모바일 화면 기반을 추가하고 장소 추천·인증 화면에 적용했다.
- 추천 요청부터 SSE 완료·실패까지 이력을 저장하고, 이력 조회·이름 변경·삭제를 실제 API와 연결했다.
- 저장한 장소 목록을 mock 데이터 대신 saved-place API로 조회·삭제하도록 전환했다.

## 주요 변경

### 공통 UI 기반

- `PageRoot`에 `full`·`contained` 레이아웃을 추가했다.
- 재사용 가능한 `Header`, `FeedbackState`를 추가했다.
- 장소 추천, 이력, 저장한 장소, 로그인·회원가입·비밀번호 재설정 화면의 중복 header·상태 UI를 공통 컴포넌트로 이관했다.
- 개발 환경에서만 `react-scan`, `react-grab`을 동적으로 로드한다. `VITE_DISABLE_REACT_DEVTOOLS`로 비활성화할 수 있다.
- `Modal`, `BottomSheet`, `OverlayShell`의 public API와 상호작용은 변경하지 않았다.

### 추천 이력 API와 SSE 영속화

- `POST /api/recommend`에서 인증된 사용자의 PENDING 이력을 먼저 생성한다.
- `GET /api/recommend/stream/:jobId`는 작업 소유자를 검증하고, 성공·실패 terminal event를 내보내기 전에 이력 결과를 저장한다.
- 다음 이력 API를 추가했다.
  - `GET /api/place-recommendation-histories`
  - `GET /api/place-recommendation-histories/:id`
  - `PATCH /api/place-recommendation-histories/:id/rename`
  - `DELETE /api/place-recommendation-histories/:id`
- 서버와 클라이언트가 공유하는 이력 REST 계약을 `packages/api-contracts`에 추가했다.
- 클라이언트 SSE 연결에 `withCredentials: true`를 적용했다.

### 이력·저장한 장소 화면

- 추천 이력 화면의 mock 데이터를 제거하고, 실제 목록 조회·결과 복원·이름 변경·삭제를 연결했다.
- 이력과 저장한 장소 목록에 loading, empty, error, retry 상태를 제공한다.
- saved-place API 어댑터를 추가하고 저장한 장소 목록/삭제를 실제 API에 연결했다.
- 저장한 장소 목록은 현재 저장된 스냅샷을 조회·삭제하는 범위다. 추천 결과 화면의 저장/해제 하트 토글은 이번 PR 범위에 포함하지 않는다.

### 테스트 정리

- 요청에 따라 페이지 컴포넌트를 직접 렌더링하던 테스트는 제거했다.
- API 어댑터 계약 테스트, 라우트 가드 테스트, 서버 이력 단위 테스트는 유지한다.
