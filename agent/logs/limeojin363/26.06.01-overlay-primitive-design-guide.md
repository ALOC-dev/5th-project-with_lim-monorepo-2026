# Overlay primitive 설계/작업 가이드

## 책임

- 공통 Overlay는 모달, 바텀시트, 날짜 선택, 위치 선택의 공통 레이어 동작만 담당한다.
- `OverlayRoot`는 portal 생성, z-index 계층, ESC 닫기, scrim click, body scroll lock, focus restore를 소유한다.
- `OverlayScrim`은 fixed viewport 배경과 pointer 이벤트만 담당하고, content 레이아웃을 알지 않는다.
- `Portal`은 `document.body` 하위 렌더링을 표준화하고 SSR/테스트 환경에서 document 부재를 방어한다.
- Dialog/BottomSheet는 표면 위치와 aria 연결만 담당하고, 버튼은 외부 의존성이라 `footerSlot`으로 받는다.
- DatePicker/LocationPicker는 Overlay를 직접 import하지 않는 순수 content로 두고, 페이지가 Overlay와 조합한다.

## Props/API

- `OverlayRoot`: `open`, `onOpenChange(open)`, `onDismiss(reason)`, `children`, `closeOnScrimClick = true`, `closeOnEscape = true`.
- `OverlayRoot`: `initialFocusRef?`, `restoreFocusRef?`, `preventScroll = true`, `zIndex?`, `ariaLabelledBy?`, `ariaDescribedBy?`.
- `OverlayScrim`: `onPointerDown?`, `visible?`, `zIndex?`; 배경색은 토큰 없으면 임시 rgba만 사용한다.
- `Portal`: `container?: HTMLElement`, `children`; 기본 container는 `document.body`.
- `BottomSheet`: `open`, `title`, `children`, `footerSlot?`, `onDismiss`, `maxHeight?`, `contentId?`.
- `Dialog`: `open`, `title`, `description?`, `children`, `footerSlot?`, `onDismiss`, `size?`.
- Picker 공통: `value`, `onChangeDraft`, `onCommit?`, `onCancel?`; 제출 버튼은 내부 생성하지 않는다.

## 구현 순서

- 1. `OverlayRoot`와 `Portal`을 먼저 추가해 `open=false`일 때 DOM을 만들지 않는 정책을 확정한다.
- 2. `OverlayRoot` mount 시 이전 activeElement를 저장하고, close/unmount 후 trigger로 focus를 복귀한다.
- 3. focus 가능한 요소 목록을 계산해 Tab/Shift+Tab 순환을 막고, 요소가 없으면 surface 자체에 focus를 둔다.
- 4. `Escape` keydown은 top overlay만 닫도록 stack id 또는 document listener 등록 순서를 관리한다.
- 5. body scroll lock은 기존 `body.style.overflow` 값을 저장/복구하고, 중첩 overlay count를 고려한다.
- 6. `OverlayScrim`은 기존 `OverlayBg`를 대체하거나 내부 구현으로 흡수하되, 호환 export는 한 번 더 검토한다.
- 7. `BottomSheet`는 Overlay 기반으로 교체하고 `max-height`, 내부 scroll, safe-area padding을 적용한다.
- 8. `Dialog`는 같은 Root 위에 중앙 surface로 만들고 `role="dialog"`, `aria-modal`을 연결한다.
- 9. DatePicker/LocationPicker는 content 컴포넌트로 구현한 뒤 페이지에서 BottomSheet/Dialog와 조합한다.

## 테스트

- OverlayRoot: `open`에 따른 portal 렌더링, ESC 닫기, scrim click 닫기/비활성 옵션을 검증한다.
- Focus: 열릴 때 초기 focus, Tab 순환, 닫힌 뒤 trigger focus 복귀를 검증한다.
- Scroll: open 중 body scroll lock, close 후 기존 overflow 복구, 중첩 overlay 복구 순서를 검증한다.
- Z-index: scrim < surface < toast/후속 시스템 순서를 상수로 고정하고 회귀 테스트 또는 스냅샷에 남긴다.
- BottomSheet: viewport 하단 fixed, `maxHeight` 내부 스크롤, `env(safe-area-inset-bottom)` padding을 확인한다.
- Dialog: role/name/description 연결과 footer slot 렌더링을 확인한다.
- Picker 조합: DatePicker는 `YYYY-MM-DD`, LocationPicker는 `{ lat, lng }[]` commit 어댑터를 별도 테스트한다.

## 리스크

- focus trap을 직접 구현하면 예외가 많다. 의존성 추가가 가능해지면 검증된 focus 유틸을 우선 검토한다.
- scroll lock은 iOS Safari에서 body와 내부 스크롤이 함께 움직일 수 있어 실제 모바일 확인이 필요하다.
- overlay stack 없이 ESC/listener를 단순 등록하면 뒤쪽 overlay가 같이 닫힐 수 있다.
- 지도 SDK나 위치 권한을 Overlay에 넣으면 재사용성이 깨진다. LocationPicker provider로만 격리한다.
- 기존 `OverlayBg` 명칭은 scrim 역할과 맞지 않는다. 제거/rename 시 import 경로 영향도를 먼저 확인한다.
