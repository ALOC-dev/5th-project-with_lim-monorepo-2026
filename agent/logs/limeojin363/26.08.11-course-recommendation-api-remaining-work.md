# 코스 추천 API·SSE·FE 연동 이후 남은 작업

## 기준

- `26.08.10-feat-history-and-bookmark-pr-description.md`의 완료 범위와 제외 범위
- `feat/course-recommendation-api`의 코스 추천 API·SSE·FE 어댑터 구현 범위

## 이번 브랜치에서 완료한 범위

- `courses`, `course_options`, `course_places`를 사용하는 코스 추천 요청·결과·옵션 상세·이력·취소·찜 API
- mock `CourseRecommendationEngine`을 연결한 SSE 진행/완료/실패/취소 이벤트
- 기존 in-memory 코스 화면 repository를 HTTP/SSE adapter로 전환
- 즐겨찾기 장소 조회와 Kakao 검색 장소를 코스 요청 snapshot으로 정규화
- 코스 옵션 4종, 빈 결과, 실패 mock outcome과 엔진 단위 테스트

## 배포·통합 전 필수 작업

1. **DB 스키마 적용**
   - `courses.input`, `courses.error_code`, `courses.error_message`, `course_options.route_path`를 대상 DB에 적용한다.
   - 현재 프로젝트의 스키마 적용 방식에 맞춰 `pnpm --filter @monorepo/server db:push`를 개발 DB에서 먼저 검증한다.
   - 운영 반영 전 기존 `courses` 행이 있을 경우, `input`의 backfill 또는 nullable 전환 후 재강화 방식을 결정한다.

2. **실제 코스 엔진 adapter 교체**
   - `apps/server/src/courseRecommendation/engine.ts`의 mock 구현을 실제 엔진·경로 탐색 구현으로 교체한다.
   - 진행 단계와 terminal event 계약은 유지하고, 장시간 작업은 서버 프로세스 메모리 대신 작업 큐/영속 job으로 운영한다.

3. **인증된 E2E 검수**
   - 스키마가 적용된 개발 DB와 로그인 세션에서 생성 → SSE → 결과 → 상세 → rename/delete/cancel → 찜 전체를 검수한다.
   - `COURSE_RECOMMENDATION_MOCK_OUTCOME=SUCCESS|EMPTY|FAILED` 각각을 서버에 설정해 결과 상태를 확인한다.

## 후속 제품 작업

1. 홈·마이페이지에서 코스 추천, 이력, 코스 찜으로 진입하는 메뉴/딥링크를 연결한다.
2. Kakao 지도 키와 실제 route path를 준비해 결과 지도에 경로·마커를 운영 환경에서 검수한다.
3. Figma 기준 390×844 세부 UI 비교(빈/오류/선택 제한 포함)와 접근성·반응형 polish를 진행한다.
4. 코스 추천 REST/SSE 라우트를 주입 가능한 storage/job dependency로 분리하고, 소유권·취소·SSE 재접속을 test-local Express E2E로 확장한다.
5. `packages/recommendation-engine`의 기존 TypeScript 오류 3건을 수정해 서버 전체 typecheck를 통과시킨다.
